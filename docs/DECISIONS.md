# Architectural Decisions

## 1. Bundle Structure
**Decision:** Monorepo with **two independent bundles**.

- **`packages/dsh-arabic-locale`**:
  - **Purpose:** Language registration and dictionaries.
  - **Host Row:** Registers Arabic as a supported language.
  - **Client Half:** Calls `ctx.locale.addLanguage` and `ctx.locale.register`.
- **`packages/dsh-rtl-layout`**:
  - **Purpose:** Visual mirroring and direction control.
  - **Host Row:** Adds a persistent settings field `ui.arabicMode`.
  - **Client Half:** Manages `document.documentElement.dir` based on the setting.

**Rationale:** Separation of concerns. A user might want the Arabic language but keep LTR (or vice versa for debugging). It also prevents a crash in the translation layer from breaking the layout.

## 2. Settings & Persistence
**Decision:** Use the official `ctx.locale` and `ConfigForms` pattern.

- **Language:** Handled by the built-in `locale` service. We only add the `ar` option.
- **RTL Mode:**
  - Defined in the `dsh-rtl-layout` Host row.
  - Persisted via the Host's settings store (similar to how `ui-theme` works).
  - Managed on the client via a `ConfigForm` for the `ui-settings` namespace.
- **Placement:** The toggle will be registered in the `settings.general.item` slot.

## 3. Implementation Order
1. **Phase 1 (Locale):** Install `dsh-arabic-locale`. Verify "العربية" appears in Settings and core UI translates.
2. **Phase 2 (Layout):** Install `dsh-rtl-layout`. Verify the root flip and "LTR Island" guards.
3. **Phase 3 (Coverage):** Harvest the shipped dictionaries, translate every mounted client bundle, and install the expanded bundle. Visual polish is deferred to the user-driven checklist (no measured CSS fix was pending).

## 4. Safety & Fallbacks
- **Safe Fallback:** If `ar` is selected but a key is missing, `ctx.locale` automatically uses `en`.
- **Reversibility:** The RTL toggle is a simple boolean; turning it off restores `dir="ltr"` immediately.
- **No-Touch Policy:** Zero modifications to `app.asar` or profile files. All changes via `plugin_manager`.

## 5. Translation Tables & Generated Coverage (Phase 3)
**Decision:** Keep a hand-curated `AR_CORE` table plus a generated `AR_PHASE3`
table, merged at activation with `Object.assign`.

- **`AR_CORE`** is the reviewed Phase 1–2 table; one-off corrections go here.
- **`AR_PHASE3`** is generated by `tools/apply-translations.cjs` from the
  dictionaries harvested out of `app.asar`; it is rewritten wholesale and never
  hand-edited. The generator fills only the block between the `PHASE3-AR`
  markers, so a DSH update can be re-covered without touching the curated table.
- **Why not one giant hand-written table:** the shipped dictionaries change
  between DSH releases. A generated table keeps the corpus and the translation
  separate, so a future upgrade is a re-harvest + batch + merge instead of a
  manual audit of 2,000 strings.
- **Scope = mounted bundles:** only the client bundles the enabled profile
  patches actually mount are translated. Unmounted experimental bundles keep
  English until enabled; translating them now would be invisible work.
- **Identifiers stay English:** tool names, slash commands, units, formats and
  protocol names are deliberately excluded from batches and fall back to English
  (listed in `docs/INVENTORY.md` §5).
- **Harvest every dictionary shape:** the shipped bundles are not uniform. Some
  dictionaries are named `en`, others `guideEn` / `accessEn` / `frequencyEn` /
  `onboardingEn` / `zoomEn` or generated `en$N`; some are spread into `en`
  (`const en = { ...guideEn, … }`); some values are arrays joined with
  `.join("\n\n")`. The harvester resolves all of these — an earlier version that
  only matched `const en = {` left the agent-preset guide dialog English, which
  the user caught after the first install. Any future "still English" report
  should first re-check the extractor's dictionary coverage.
- **Batch translation with mechanical validation:** `tools/locale-batch.cjs`
  splits the gaps into area batches; `tools/check-translation-part.cjs` enforces
  placeholder/whitespace/no-zero-width invariants before a batch can be merged.
  This made a six-agent parallel translation pass safe to merge.
